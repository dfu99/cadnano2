# Lessons — cadnano2

_Hard-won lessons, gotchas, and things that broke before._
_This file is append-mostly. Only remove entries proven wrong._

## General

- Headless testing of AgentMethods works with `QT_QPA_PLATFORM=offscreen` + `cadnano.initAppWithGui()` + a MockDC class. `HeadlessCadnano` is missing `documentWasCreatedSignal`, so the GUI init path (with offscreen platform) is required.
- Insertions in cadnano are position-based, not strand-based. Adding an insertion to a scaffold strand at index X also appears on the staple at index X. `listInsertions` will report both scaffold and staple entries for the same position — this is correct. When adding insertion patterns, only add to one strand type per position.
- `removeCrossoversForPair` removes more crossovers than `addCrossoversForPair` creates — because `addCrossoversForPair` creates double crossovers (2 half-crossovers as one logical unit), but the removal counts each half-crossover individually. This is cosmetic (removal is correct) but the count mismatch can be confusing.
- The DocumentController method for creating a honeycomb part is `actionAddHoneycombPartSlot()`, not `actionNewHoneycombPartSlot()`.
- The autobreak plugin's `__init__.py` has legacy `import cadnano` (not `cadnano2`). To import `autobreak.py` functions from agent code, use `importlib.util` to load the file directly and bypass the package init.
- `Oligo.color()` not `Oligo.getColor()` — cadnano2 uses `color()` as property-style method.
- 1×N linear chain scaffold routing only works for even N ≥ 4. Odd N is geometrically impossible: the honeycomb crossover table ordering (High = Low + 1 for all directions) makes the interior helix constraint (pair_ret < pair_out) incompatible with the end helix parity constraint (even end helix needs pair_out < pair_ret) for adjacent same-direction helices. The 2×N grid avoids this because cross-row connections use different directions with different crossover tables.
- `moveCrossover` had a bug: the overlap check rejected moves even when the only "neighboring" strands were the other half-crossover strands being moved simultaneously. Fixed by collecting `moving_strands` set and skipping overlap checks against co-moving strands.
- `listCrossovers` and `getValidCrossoverPositions` return strings, not dicts. To use their output programmatically, parse with regex + `ast.literal_eval`.
- tacoxDNA's initial nucleotide placement depends ONLY on helix lattice positions (row, col), NOT on crossover connectivity. A design with all crossovers and one with zero crossovers produce identical 3D coordinates. The geometric reward (flatness, planarity, circularity) catches wrong helix arrangements (flat sheet vs grid: 0.95 vs 0.42) but cannot detect missing crossovers. To get crossover-sensitive 3D feedback, you would need oxDNA molecular dynamics relaxation (too slow for training). Use geometric reward + structural verifier together.
- Staple double crossovers have widely spaced half-crossover positions (e.g., low_idx=63, high_idx=83) unlike scaffold crossovers which are adjacent (88, 89). `moveCrossover` doesn't yet handle staple crossovers correctly — the intermediate strand segments between the two half-crossover positions aren't accounted for.
- Headless screenshot capture works: `scene.render(painter, source=items_rect)` on a `QImage` with `QT_QPA_PLATFORM=offscreen`. Use `items_rect = scene.itemsBoundingRect()` with margins for good framing.
- `from cadnano2.views.agent.agentmethods import AgentMethods` must be done AFTER `cadnano.initAppWithGui()` — importing AgentMethods triggers Qt font initialization which crashes if no QApplication exists. Always: `os.environ['QT_QPA_PLATFORM'] = 'offscreen'` → `initAppWithGui()` → `import AgentMethods`.
- tacoxDNA (`cadnano_oxDNA.py`) outputs files named `<input>.oxdna` and `<input>.top` (appends extension to the full input filename including `.json`). 1 oxDNA length unit = 0.8518 nm. tacoxDNA needs `he` (hexagonal) for honeycomb lattice designs.
- For PCA-based shape analysis of oxDNA coordinates: PC1=length, PC2=width, PC3=thickness. Flatness ratio = thickness/length. A 6-helix x 126bp flat sheet gives ~0.058 flatness and ~0.63 nm planarity RMS (about 1 DNA diameter thick).
- `deleteExposedFragments` (OR condition: either end free) is too aggressive after placing non-loop crossover patterns — it removes strands that are part of the routing but have one exposed end. Use `deleteOrphanFragments` (AND condition: both ends free) to only remove edge stubs outside the crossover range.
- Different honeycomb neighbor directions (p0, p1, p2) have different valid crossover position offsets. In a 4-helix linear chain, H0-H1 (p0) has edges at low_idx 1/116, while H2-H3 (p2) has edges at 4/120. The PI's observation "not necessarily in the same positions" is because each pair uses a different direction's crossover tables.
- Scaffold crossover edge detection: marking both first AND last valid positions as "edges" for half-crossovers is wrong. Each helix pair needs at most ONE half-crossover (the routing turn), determined by helix parity: even parity exits at the HIGH (rightmost) position, odd exits at LOW (leftmost). The routing turn must be force-included in recommended positions because the spacing filter (21bp) can exclude it when it's close to the last interior position.
- When creating multiple cadnano designs in the same process, call `dc.newDocument()` between designs to reset the document. Without this, `_make_methods(app)` gets the same `documentControllers` and helices persist from previous designs.
- Cross-section circularity distinguishes shape classes: flat sheet ~0.48, tube ~0.55, 2×3 grid ~0.84 (near-square cross-section). Higher circularity = more compact cross-section.
- Half crossover handedness (left vs right): A full double crossover consists of a LEFT half (at the Low index) and a RIGHT half (at the High index). `honeycombScafLow` positions are Left half crossover positions, `honeycombScafHigh` positions are Right half crossover positions. At the LEFT side of the structure (scaffold turn), use a RIGHT half crossover (High index position). At the RIGHT side, use a LEFT half crossover (Low index position). **Use `createHalfCrossover` directly at the correct table position** — the double-then-remove approach (create double, remove one half) does NOT produce correct visual results. `createHalfCrossover` handles strand ordering automatically via `_isHighCrossoverPosition`: Low positions use even→odd (even is 5p), High positions use odd→even (odd is 5p).
- **Serpentine scaffold routing cannot use `createXover`**: `part.createXover()` splits strands at the crossover position, and subsequent crossovers can split already-connected strands, breaking the path. For serpentine (one-crossover-per-pair) routing, create correctly-sized strands between crossover positions and connect them directly using `strand5p.setConnection3p(strand3p)` + `strand3p.setConnection5p(strand5p)` + oligo merging. This bypasses the split mechanism entirely and produces a single continuous scaffold oligo.
- **Rectangular origami scaffold uses ~91% of helix length**: In honeycomb lattice, crossover positions at helix edges are at offset 1-4 (not 0), so the scaffold doesn't reach the very ends. For m13mp18 (7249 nt) on 24 × 294bp helices, the routed scaffold is ~6762 bp — the remaining 487 nt are consumed by single-base insertions (also serves as twist correction).
- **autoBreak `from . import staplegraph` fails** when called from scripts outside the package. Fix: use `importlib.util.spec_from_file_location` to pre-load `staplegraph.py` into `sys.modules['cadnano2.plugins.autobreak.staplegraph']` before importing `autobreak.py`.
- **Honeycomb grid default size is 30 rows × 32 columns**: Helix positions must stay within (0-29, 0-31). A 24-helix row starting at column 20 reaches column 43 (crash). Start at column 4 instead: 4+23=27 < 32.
- **oxDNA input files need `time_scale = linear`, `refresh_vel = true`, and `trajectory_file`**: These mandatory keys are not obvious from examples. Without them, oxDNA fails with cryptic error messages.
- **oxDNA from source requires CMake < 4.x fix**: The `CMP0037` policy must be set to NEW (not OLD) in `CMakeLists.txt`. CUDA build fails with modern cmake/nvcc; CPU-only build works. Use `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`.
- L-shaped honeycomb designs (3 horizontal + 2 vertical helices) produce a thicker cross-section (4.6 nm vs 2.4 nm flat sheet) and higher planarity RMS (1.28 nm) due to the out-of-plane bend at the junction. The PCA-based analysis captures this as increased flatness ratio (0.11 vs 0.058).
- **oxDNA relaxation: `max_backbone_force_far` is critical**. The old pipeline used 10.0 for MD relaxation — far too permissive, letting the structure blow apart. The PACE bricks_crystal recipe uses a staged approach: 0.1 (gentle relax) → 1.0 (production relax). The gentle stage lets the structure settle without the backbone flying apart, then the production stage allows more realistic forces. Also: John thermostat (Langevin, `diff_coeff=2.5`, `newtonian_steps=103`) is proven stable for DNA origami on PACE; Bussi thermostat with tau=1000 was not tested on production structures. Use `dt=0.003` (not 0.002), `verlet_skin=0.5` (not 0.15) for MD, and `salt=1.0` for minimization.
